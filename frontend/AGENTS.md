# frontend — AGENTS.md

Next.js 16 App Router client for clipsieve. Thin: all state from `/api/*` (Next rewrite to FastAPI :8000) and the `RunEvent` SSE stream.

## Contracts
- Package name `frontend` (ESM, `"type": "module"`); scripts `dev`, `build`, `typecheck`, `test`, `e2e`.
- `src/lib/types.ts` is GENERATED by `packages/schema`; never edit.
- `src/lib/poll.ts` `pollUntil(fetch, ok, {intervalMs, maxMs, cancel?})` calls `fetch` now and every `intervalMs` until `ok`, cancel or `maxMs`; it resolves with the accepted value, else the last fetched, else null (failed fetches are skipped). Fake-timer tested.
- `src/lib/api.ts` is the only place that calls `fetch` against the API. `src/lib/useRunEvents.ts` is the only place that opens an `EventSource`, and only inside effects (SSR-safe).
- `useRunEvents(runId, {mode: "live"} | {mode: "replay", speed, playing}, factory?)` returns `{ state, events, connected, progress }`. Live tails `eventsUrl(runId, lastSeq)`; on `error` it closes, waits 1 s and reopens with the last applied seq (the overlap is a reducer no-op), and stops at the terminal event by the server's rule: `done`, or any event in stage `failed`. Replay loads the whole log from `after=0` (the server closes after terminal; an error ends the load with what arrived), then one self-rescheduling timer plays it at original gaps / `speed`; pausing or changing speed keeps the cursor and the time already waited in the current gap, so no event is skipped or repeated. `progress` is played/total in replay, `done ? 1 : 0` live. `connected` is true only while a source is open. A new `runId` or `mode` resets everything during render. `factory` (tests inject a fake) must be referentially stable.
- `next.config.ts` sets `compress: false`. Verified on Next 16.3 dev: with the default gzip, `/api/runs/{id}/events` through :3000 answered with `Content-Encoding: gzip` and held every event back until the stream closed (the same events were immediate on :8000); with `compress: false` the header is gone and events pass through within milliseconds. The API is proxied, so Next has nothing of its own worth compressing; a production proxy may compress static assets, never `text/event-stream`. The hook clears the "reconnecting…" badge on the `open` event; the backend guarantees it fires promptly by sending a `: connected` comment first and `: ping` comments while idle.
- `src/lib/events.ts` is a pure reducer (`reduceEvent`, `reduceAll`, `answersPerSecond`); components never derive state from raw events. It never mutates its inputs, returns the same state for `seq <= lastSeq` (so a reconnect with `after=N` that replays events is a no-op), treats `done` or `stage_changed` to `failed` as terminal, and takes the `done` event's counters as authoritative. Before `done` it derives `elapsed_s` from the first event's `ts` and `jev_cost_usd` from tokens at `JEV_USD_PER_MILLION_INPUT`. `readyPlan(events)` returns the plan of the latest `plan_ready` that carries one. `plannerError(events)` is the message of the latest `error` whose `where` starts with `planner`, else null. `failureMessage(errors)` is the last error marked `recoverable: false` (the runner's `_fail` writes it right before the failed stage), else the last error with a message, else null.
- `src/lib/__fixtures__/`: five fixture posts (`local:fx-001..005`, two English, three Chinese) and a valid `FIXTURE` run log (seq 1..N, monotonic `ts`). `run-events.json` is GENERATED from `run-events.ts` by `bun run scripts/write-fixture-events.ts` (in `frontend/`; it Biome-formats its output). Never hand-edit it; `events.test.ts` fails when it drifts. Reducer tests cut the log at pinned seqs; changing the fixture means updating those pins.
- Every user-visible string goes through `t(key, locale)` from `src/lib/i18n.ts`; keys live in `src/lib/i18n/en.ts` and `zh.ts`. Adding a key means adding it to both.
- Post ids contain `:`; `encodeURIComponent` them in every URL. Run ids too, in hrefs and `router.push`.
- `src/app/layout.tsx` (server) keeps the Geist `--font-geist-*` variables that `globals.css` maps to `--font-sans`/`--font-mono`, mounts `AppHeader` and `<Toaster />`, and takes metadata from the `en` dictionary (the client locale is unknown on the server). Pages fetch in client effects only, with an `active` flag cleanup; a toast that needs the locale goes through `useEffectEvent` so the load effect does not refetch on a locale switch.
- `/` is `BriefForm` + `RecentRuns` (`src/components/brief/`). `BriefForm` submits only healthy, ticked adapters; quantity inputs hold raw text, parsed at submit to 1..5000 (blank or invalid is 500); the rubric falls back to the first pack until the user picks one, because packs load after mount. The rubric picker is a native `<select>` styled like `ui/input`: the shadcn `Select` portals, and jsdom cannot drive it with `userEvent.selectOptions`.
- `/runs/[id]/plan` (`src/app/runs/[id]/plan/page.tsx`, client) loads `getRun` (an `active`-flag effect keyed on the id and a Retry counter; failure shows the API detail and Retry). The stored plan wins over the log because it carries saved edits and `approved_at`; only while it is null does the page tail `useRunEvents(id, {mode: "live"})` output through `readyPlan`. With no plan, a `plannerError` in the log (the API's `_plan` emits `error {where: planner, recoverable: true}`) replaces the pending text with a destructive `Alert` (`plan.failed` + message) and a `Start over` link to `/`; a stored plan still shows the editor. Save is `savePlan`; Approve is `savePlan` then `approveRun`, then `router.push` to the encoded `/runs/{id}`; errors toast the `ApiError` detail. Async handlers skip state updates after unmount.
- `PlanEditor({ plan, onSave, onApprove, busy })` (`src/components/plan/`) seeds a draft from `plan` once (remount with a new `key` to reseed). Query rows carry client-only ids that are stripped on submit, so the backend (`extra="forbid"`) receives only `platform`, `query`, `lang`. Platform is a native `<select>` of the plan's `quantities` keys. Quantities hold raw text, parsed at submit to 1..5000 (blank or invalid keeps the planned number). Persona fit always renders and submits exactly five levels. Save accepts a work-in-progress draft; Approve needs at least one query, text in every query and all five levels (errors are i18n keys). A plan with `approved_at` is read-only and links to its run.
- `/runs/[id]` (`src/app/runs/[id]/page.tsx`, client) feeds `useRunEvents(id, {mode: "live"})` into `Dashboard`. `getRun` loads once per id (an `active`-flag effect; the load-error toast goes through `useEffectEvent`, so a locale switch does not refetch). `total` is the larger of the stored plan's summed quantities (else the run's) and the collected count. While not `done`, Pause/Resume call `api.pauseRun`/`resumeRun` (busy-guarded, `ApiError` detail toasts, no state update after unmount). The API answers before the pipeline reaches its pause point (`POST /pause` returns `paused: false`; `/resume` while busy returns `paused: true`), so a 2xx is treated as accepted intent: the local `paused` flips to the requested value at once, then `pollUntil(getRun)` every 500 ms for up to 10 s until the server agrees, falling back to the server's last answer; a new toggle cancels the previous poll. The page passes `run.error` to `Dashboard` as `error`. A failed load still shows the live dashboard, without controls.
- `Dashboard({ runId, state, events, connected, mode, total?, controls?, error? })` (`src/components/dashboard/`) is presentational: it renders a `DashboardState` and never opens a stream. `mode` is `"live" | "replay"`. The header has a stage badge, a connection badge (live only, hidden once `done`; a replay plays a log it already holds), `controls`, a link to `/runs/{id}/replay` (live) or back to `/runs/{id}` (replay), and, only when the stage is `done` (`state.done` is also true for a failed run), `/runs/{id}/report` (run id encoded). When `state.stage` is `failed` a destructive shadcn `Alert` (`run.failed`) shows `failureMessage(state.errors)`, else the `error` prop (the stored run's `error`). `total` defaults to the collected count. A post is named by `title || caption || id` (`||`, so an empty title falls through). Regions:
  - `Counters({ counters, rate })`: six tiles. Elapsed is the reducer's `elapsed_s` (client-side from `startedAt` until `done`), shown with the `duration.*` keys.
  - `PostGrid({ runId, posts, total })`: renders at most `MAX_TILES` (2000) tiles; the progress label counts every post. Each tile has `data-state` (`collected | dropped_pass_one | judged | shortlisted | review | judge_failed`), a distinct `TILE_STATE_CLASS`, and a corner icon for shortlisted, review and judge_failed. The thumbnail is `mediaUrl(runId, post.id, "thumb.jpg")`; on a load error the tile shows its kind icon (`Film`/`Images`) and retries once when its state changes. Tiles are memoised; the reducer keeps untouched tiles by reference.
  - `CurrentItem({ latest })`: one row per answer; noul shows its probability, choice and score their confidence, as shadcn `Progress`.
  - `Aggregates({ aggregates })`: only `hook_type`, `format`, `persona_fit` (rounded levels shown as `Level n`).
  - `ReviewBucket({ review, posts })`: the count and a dialog listing the posts. `DialogContent` gets `showCloseButton={false}` (its generated sr-only label is untranslated) and a translated `DialogClose` button.
- `/runs/[id]/report` (`src/app/runs/[id]/report/page.tsx`, client) loads `getReport`, then every post through `getPosts` in pages of 500 (offset = posts so far, until `total` or an empty page), in one `active`-flag effect keyed on the id and a Retry counter; a result for a previous id is ignored. A 404 from `getReport` is the translated "not ready" state; other failures show the API detail and Retry. Every state but loading links back to the encoded `/runs/{id}`.
- `ReportView({ report, posts })` (`src/components/report/`, `posts` keyed by post id) renders patterns, clips, gaps, concepts and, when present, caveats as one `Card` each; an empty section says so, and the articles inside are plain markup, never nested cards. Each cited id is an `xs` outline button. An id missing from `posts` (own keys only, via `Object.hasOwn`) is disabled with the translated "not found" `title` and never opens a dialog; it overrides the stock `disabled:pointer-events-none` with `disabled:pointer-events-auto` so the hover reaches it and the tooltip shows. Hook quotes render in `<q>`. `PostDialog({ view, open, onOpenChange })` stays shut without a view; it shows the post title (`title || caption || id`, like the tiles), id and kind, the caption, and the latest pass's answers via `answerLabel`, with `showCloseButton={false}` and a translated `DialogClose`.
- `/runs/[id]/replay` (`src/app/runs/[id]/replay/page.tsx`, client) feeds `useRunEvents(id, {mode: "replay", speed, playing})` into `Dashboard` (default playing, 4x) with `ReplayControls({ playing, speed, progress, done, total, onToggle, onSpeed })` in the `controls` slot: play/pause toggle (aria-label), `SPEEDS = [1, 4, 16]` buttons (active one `aria-pressed`, default variant), and a `Progress` with `done / total events` (`total` = events played / progress; 0 until the first event).
- API origin: `CLIPSIEVE_API_ORIGIN` (default `http://localhost:8000`), read when `next.config.ts` loads (`next dev` start, `next build`; baked into the build's routes manifest).
- Env: Next reads `frontend/.env*` and the process environment; `bun run dev` from the root also loads the root `.env`. Empty values fall back to defaults (`||`, not `??`).

## Component map
- `src/app/page.tsx` -> `brief/BriefForm` + `brief/RecentRuns`
- `src/app/runs/[id]/plan/page.tsx` -> `plan/PlanEditor` (live `useRunEvents` until a `plan_ready` plan arrives; a planner `error` shows the failure instead)
- `src/app/runs/[id]/page.tsx` -> `dashboard/Dashboard` (live) with pause/resume controls
- `src/app/runs/[id]/report/page.tsx` -> `report/ReportView` + `report/PostDialog`
- `src/app/runs/[id]/replay/page.tsx` -> `dashboard/Dashboard` (replay) + `dashboard/ReplayControls`

## Data flow
`EventSource` (`useRunEvents`) -> `reduceEvent` -> `DashboardState` -> components. Replay reads the whole log over the same SSE endpoint (`after=0`, the server closes after `done` or a `failed`-stage event), then re-emits it on `ts` deltas / speed. Live reconnect uses `after=lastSeq`; the reducer ignores `seq <= lastSeq`.

## Conventions
- Native `<select>` for form selects (`BriefForm`, `PlanEditor`); shadcn `Select` portals and jsdom cannot drive it.
- Tiles request `mediaUrl(runId, post.id, "thumb.jpg")` (`/api/runs/{id}/media/{post_id}/thumb.jpg`) and fall back to a kind icon on error.
- `data-testid="tile-<post_id>"` and `data-state` on grid tiles are part of the e2e contract.
- Grid tiles and "Too close to call" list entries are buttons that open `report/PostDialog` for that post (caption, latest Jev answers, a link to the original post). The reducer keeps each pass's `JudgeResult` on the tile (`PostTile.judge`), so the dialog works live and in replay without a fetch; `tileView(tile)` builds the `PostView` it expects.
- Fixture event log: `src/lib/__fixtures__/run-events.ts` (builder) and generated `run-events.json` (`bun run scripts/write-fixture-events.ts` in `frontend/`).

## Tooling
- Biome via ultracite; no eslint, no prettier. `biome.jsonc` has `"extends": "//"`, the root config (Biome 2.5 accepts `"//"` only as a string, not inside an array). The ultracite `react` and `next` presets are in the root `biome.jsonc`. Here, `files.includes` replaces the root list. It excludes the generated `src/lib/types.ts` and the shadcn `src/components/ui`.
- `frontend/biome.jsonc` overrides `useFilenamingConvention` to allow kebab-case, camelCase and PascalCase frontend-wide, because the plan names components `LocaleSwitch.tsx`, `BriefForm.tsx` and hooks `useRunEvents.ts`. The override replaces the rule `options`, so it restates ultracite's `requireAscii: true` (its only other option); keep it in sync if ultracite changes.
- shadcn style `radix-nova` (Radix primitives from `radix-ui`, `asChild` API), icons `lucide-react`. Installed: badge, button, card, checkbox, dialog, input, progress, select, slider, sonner, table, tabs, textarea, tooltip, alert. Components in `src/components/ui/` are generated: re-add with `bunx --bun shadcn@latest add <name>` instead of hand-editing. They import `cn` from the `cn` package. `src/lib/utils.ts` wraps it for the `@/lib/utils` alias. Toasts need `<Toaster />` from `ui/sonner`; the root layout mounts it. Tooltips need a `<TooltipProvider>`, not mounted yet.
- Vitest + Testing Library + jsdom for unit tests (`src/**/*.test.{ts,tsx}`, explicit `vitest` imports, no globals); Playwright for `e2e/run-flow.spec.ts` (see E2E below). Testing Library auto-cleans only with globals, so `vitest.setup.ts` registers `afterEach(cleanup)`.
- The ultracite React rules reject inline handler props (`noJsxPropsBind`) and `cond && <X/>` on non-booleans (`noLeakedRender`): wrap handlers in `useCallback` (per-item handlers go in a small row component) and render with `cond ? <X/> : null`.
- React `act()` flushes renders and effects only when its callback returns. A timer chain where each step waits for a re-render advances one step per `act(advanceTimersByTime)`; schedule the next timer from the timer callback instead (as `useRunEvents` replay does).
- Install with `bun add` here; the single lockfile is the root `bun.lock`. Never create `frontend/bun.lock`.

## E2E
- `cd frontend && bun run e2e` runs one Playwright flow (`e2e/run-flow.spec.ts`) in Chromium: brief, plan approve, live dashboard to Done (collected 5, shortlisted tile), report citation dialog, replay at 16x to five tiles.
- `playwright.config.ts` starts both servers: the backend (`uv run uvicorn clipsieve.app:app --port 8000` from `../backend`, `CLIPSIEVE_EXPLAIN_BACKEND=fake`, a fresh `mkdtemp` `CLIPSIEVE_DATA_DIR` per suite run) and `bun run dev` on :3000. `reuseExistingServer` is on outside CI, so a stale server on :8000 or :3000 is reused with its old data; free the ports for a clean run.
- Needs `uv`, Bun and the browser once: `bunx playwright install chromium`. No network beyond localhost. Output dirs `test-results/` and `playwright-report/` are git-ignored.

# frontend — AGENTS.md

Next.js 16 App Router client for clipsieve. Thin: all state from `/api/*` (Next rewrite to FastAPI :8000) and the `RunEvent` SSE stream.

## Contracts
- Package name `frontend` (ESM, `"type": "module"`); scripts `dev`, `build`, `typecheck`, `test`, `e2e`.
- `src/lib/types.ts` is GENERATED by `packages/schema`; never edit.
- `src/lib/api.ts` is the only place that calls `fetch` against the API. `src/lib/useRunEvents.ts` is the only place that opens an `EventSource`, and only inside effects (SSR-safe).
- `useRunEvents(runId, {mode: "live"} | {mode: "replay", speed, playing}, factory?)` returns `{ state, events, connected, progress }`. Live tails `eventsUrl(runId, lastSeq)`; on `error` it closes, waits 1 s and reopens with the last applied seq (the overlap is a reducer no-op), and stops at the terminal event by the server's rule: `done`, or any event in stage `failed`. Replay loads the whole log from `after=0` (the server closes after terminal; an error ends the load with what arrived), then one self-rescheduling timer plays it at original gaps / `speed`; pausing or changing speed keeps the cursor and the time already waited in the current gap, so no event is skipped or repeated. `progress` is played/total in replay, `done ? 1 : 0` live. `connected` is true only while a source is open. A new `runId` or `mode` resets everything during render. `factory` (tests inject a fake) must be referentially stable.
- SSE through the Next dev rewrite can be buffered by response compression; that is a backend/proxy concern (plan 03), not the hook's.
- `src/lib/events.ts` is a pure reducer (`reduceEvent`, `reduceAll`, `answersPerSecond`); components never derive state from raw events. It never mutates its inputs, returns the same state for `seq <= lastSeq` (so a reconnect with `after=N` that replays events is a no-op), treats `done` or `stage_changed` to `failed` as terminal, and takes the `done` event's counters as authoritative. Before `done` it derives `elapsed_s` from the first event's `ts` and `jev_cost_usd` from tokens at `JEV_USD_PER_MILLION_INPUT`. `readyPlan(events)` returns the plan of the latest `plan_ready` that carries one.
- `src/lib/__fixtures__/`: five fixture posts (`local:fx-001..005`, two English, three Chinese) and a valid `FIXTURE` run log (seq 1..N, monotonic `ts`). `run-events.json` is GENERATED from `run-events.ts` by `bun run scripts/write-fixture-events.ts` (in `frontend/`; it Biome-formats its output). Never hand-edit it; `events.test.ts` fails when it drifts. Reducer tests cut the log at pinned seqs; changing the fixture means updating those pins.
- Every user-visible string goes through `t(key, locale)` from `src/lib/i18n.ts`; keys live in `src/lib/i18n/en.ts` and `zh.ts`. Adding a key means adding it to both.
- Post ids contain `:`; `encodeURIComponent` them in every URL. Run ids too, in hrefs and `router.push`.
- `src/app/layout.tsx` (server) keeps the Geist `--font-geist-*` variables that `globals.css` maps to `--font-sans`/`--font-mono`, mounts `AppHeader` and `<Toaster />`, and takes metadata from the `en` dictionary (the client locale is unknown on the server). Pages fetch in client effects only, with an `active` flag cleanup; a toast that needs the locale goes through `useEffectEvent` so the load effect does not refetch on a locale switch.
- `/` is `BriefForm` + `RecentRuns` (`src/components/brief/`). `BriefForm` submits only healthy, ticked adapters; quantity inputs hold raw text, parsed at submit to 1..5000 (blank or invalid is 500); the rubric falls back to the first pack until the user picks one, because packs load after mount. The rubric picker is a native `<select>` styled like `ui/input`: the shadcn `Select` portals, and jsdom cannot drive it with `userEvent.selectOptions`.
- `/runs/[id]/plan` (`src/app/runs/[id]/plan/page.tsx`, client) loads `getRun` (an `active`-flag effect keyed on the id and a Retry counter; failure shows the API detail and Retry). The stored plan wins over the log because it carries saved edits and `approved_at`; only while it is null does the page tail `useRunEvents(id, {mode: "live"})` output through `readyPlan`. Save is `savePlan`; Approve is `savePlan` then `approveRun`, then `router.push` to the encoded `/runs/{id}`; errors toast the `ApiError` detail. Async handlers skip state updates after unmount.
- `PlanEditor({ plan, onSave, onApprove, busy })` (`src/components/plan/`) seeds a draft from `plan` once (remount with a new `key` to reseed). Query rows carry client-only ids that are stripped on submit, so the backend (`extra="forbid"`) receives only `platform`, `query`, `lang`. Platform is a native `<select>` of the plan's `quantities` keys. Quantities hold raw text, parsed at submit to 1..5000 (blank or invalid keeps the planned number). Persona fit always renders and submits exactly five levels. Save accepts a work-in-progress draft; Approve needs at least one query, text in every query and all five levels (errors are i18n keys). A plan with `approved_at` is read-only and links to its run.
- API origin: `CLIPSIEVE_API_ORIGIN` (default `http://localhost:8000`), read when `next.config.ts` loads (`next dev` start, `next build`; baked into the build's routes manifest).
- Env: Next reads `frontend/.env*` and the process environment; `bun run dev` from the root also loads the root `.env`. Empty values fall back to defaults (`||`, not `??`).

## Next 16 notes (verified against node_modules/next/dist/docs on scaffold)
Docs live at `frontend/node_modules/next/dist/docs/` (Bun isolated linker: `frontend/node_modules/next` links into the root `node_modules/.bun/`; there is no root `node_modules/next`).
- `next.config.ts` `rewrites()` (sync or async) returns `{ source, destination }[]` (optional `basePath`, `locale`, `has`, `missing`), or `{ beforeFiles, afterFiles, fallback }`. A plain array runs as `afterFiles`: after pages and `public/`, before dynamic routes. External destinations are allowed. (`01-app/03-api-reference/05-config/01-next-config-js/rewrites.md`)
- `params` (and `searchParams`) are Promises in `page`, `layout`, `route`, `default`; Next 16 removed sync access. Server components `await params`; a client page uses `use(params)` or `useParams()` from `next/navigation` (works anywhere in the client tree). Global `PageProps<"/route">`, `LayoutProps<"/route">`, `RouteContext<"/route">` type them. (`03-file-conventions/dynamic-routes.md`, `page.md`, `04-functions/use-params.md`, `02-guides/upgrading/version-16.md`)
- `"use client"` goes at the very top of the file, before imports. It marks a client entry point; only files imported directly by Server Components need it. Props crossing it must be serializable. A `page.tsx` may itself be `"use client"`. (`01-directives/use-client.md`)
- `PageProps`/`LayoutProps` come from `.next/types`, written by `next typegen`, `next dev` or `next build`. A clean checkout fails `tsc` without them, so `typecheck` is `next typegen && tsc --noEmit` (`06-cli/next.md`).
- `middleware.ts` is now `proxy.ts` with an exported `proxy` function (nodejs runtime only). Turbopack is the default for dev and build. `next lint` is gone and `next build` does not lint. `serverRuntimeConfig`/`publicRuntimeConfig` are removed; use env vars. `next dev` writes to `.next/dev` and a lockfile blocks a second `next dev` in the same project. (`02-guides/upgrading/version-16.md`)
- Vitest cannot render async Server Components. Unit-test sync components and cover async ones with Playwright. (`02-guides/testing/vitest.md`)

## Tooling
- Biome via ultracite; no eslint, no prettier. `biome.jsonc` has `"extends": "//"`, the root config (Biome 2.5 accepts `"//"` only as a string, not inside an array). The ultracite `react` and `next` presets are in the root `biome.jsonc`. Here, `files.includes` replaces the root list. It excludes the generated `src/lib/types.ts` and the shadcn `src/components/ui`.
- `frontend/biome.jsonc` overrides `useFilenamingConvention` to allow kebab-case, camelCase and PascalCase frontend-wide, because the plan names components `LocaleSwitch.tsx`, `BriefForm.tsx` and hooks `useRunEvents.ts`. The override replaces the rule `options`, so it restates ultracite's `requireAscii: true` (its only other option); keep it in sync if ultracite changes.
- shadcn style `radix-nova` (Radix primitives from `radix-ui`, `asChild` API), icons `lucide-react`. Components in `src/components/ui/` are generated: re-add with `bunx --bun shadcn@latest add <name>` instead of hand-editing. They import `cn` from the `cn` package. `src/lib/utils.ts` wraps it for the `@/lib/utils` alias. Toasts need `<Toaster />` from `ui/sonner`; the root layout mounts it. Tooltips need a `<TooltipProvider>`, not mounted yet.
- Vitest + Testing Library + jsdom for unit tests (`src/**/*.test.{ts,tsx}`, explicit `vitest` imports, no globals); Playwright for `e2e/run-flow.spec.ts`. Testing Library auto-cleans only with globals, so `vitest.setup.ts` registers `afterEach(cleanup)`.
- The ultracite React rules reject inline handler props (`noJsxPropsBind`) and `cond && <X/>` on non-booleans (`noLeakedRender`): wrap handlers in `useCallback` (per-item handlers go in a small row component) and render with `cond ? <X/> : null`.
- React `act()` flushes renders and effects only when its callback returns. A timer chain where each step waits for a re-render advances one step per `act(advanceTimersByTime)`; schedule the next timer from the timer callback instead (as `useRunEvents` replay does).
- Install with `bun add` here; the single lockfile is the root `bun.lock`. Never create `frontend/bun.lock`.

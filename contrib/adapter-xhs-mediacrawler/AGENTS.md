# contrib/adapter-xhs-mediacrawler — AGENTS.md

Community adapter. Inherits the root AGENTS.md; these rules are additive.

## Disclaimer

Browser-session adapter. It uses the user's own logged-in Chrome, either through direct web API calls (default) or through a local MediaCrawler checkout (fallback runner; NON-COMMERCIAL LEARNING LICENSE 1.1). It is not part of core, is not covered by clipsieve's Apache-2.0 grant for MediaCrawler itself, and the user is responsible for platform terms and applicable law. See `README.md`.

## Contract

- Registers `xiaohongshu = "clipsieve_xhs.adapter:XhsMediaCrawlerAdapter"` in entry point group `clipsieve.adapters`.
- **The core package never imports `clipsieve_xhs`.** If you need something from here in `backend/`, it belongs in the `Adapter` protocol instead.
- Two runners behind `RunnerProtocol`, chosen by `CLIPSIEVE_XHS_RUNNER` (`adapter.py::_runner_from_settings`; an injected `runner` wins). `api` (default, `api_runner.py`): the user's xiaohongshu.com cookies are read from their own Chromium over CDP (`cdp_cookies.py`, `Storage.getCookies`, never stored or logged), every request is signed with `xhshow` (`api_client.py`, `x_rap=True` so `x-rap-param`, which xhshow documents as required by the search and feed endpoints (not yet verified live), is sent, plus every other signed header in `SIGNED_HEADER_NAMES`) and carries the browser header set (`BROWSER_HEADERS`: the browser's `User-Agent`, matching client hints, `Sec-Fetch-*`); `code -104` (account-level risk control, not a signing defect) is raised as `XhsLoginRequired` with a message that says to check the browser tab and retry later; search uses `note_type=1` when `CLIPSIEVE_XHS_NOTE_KINDS=video`, one detail request per note supplies the video stream URL, comments are opt-in (`CLIPSIEVE_XHS_COMMENTS`). Requests are serial with a jittered interval (`CLIPSIEVE_XHS_REQUEST_INTERVAL_S`); rate-limit codes back off at most twice (three attempts). Transport failures (`httpx.HTTPError`) and signer `ValueError`s surface as `XhsApiError` with the exception type name only (signer text cut to 120 chars), never the request, response or cookies. A `XhsLoginRequired` (login expired, -104, verification) or `XhsRateLimited` from the search or a detail request halts the runner: the page is returned with `fatal=True`, every later `search` for that run is refused without a request or cookie read (`fatal=True`, error `halted: ...`), and `healthcheck` clears the halt and reports it once in its message (`ok=True`), so the next run (core healthchecks at run start) gets one fresh attempt with re-read cookies instead of being skipped. `search_only(keyword)` is one search request with no details, for the probe. The api runner's `httpx.Client` is its own (`follow_redirects=False`, 15 s), never the adapter's media-download client. `XhsApiRunner` is imported lazily, so a MediaCrawler-only install still imports the adapter.
- `mediacrawler` (fallback, `runner.py`): never vendor MediaCrawler files; drive the checkout at `CLIPSIEVE_XHS_MEDIACRAWLER_DIR` as a subprocess with cwd = the checkout and `--save_data_path <workdir>`, and parse `<workdir>/xhs/jsonl/`. The checkout stays clean.
- The adapter ignores `RunnerOutput.returncode`: it logs each entry of `errors` (`xhs.runner.error`) and yields whatever notes came back, for both runners. `RunnerOutput.fatal` (api runner only; the MediaCrawler runner never sets it) means the session is dead for the run: the adapter yields that page's notes, then raises `RuntimeError("xiaohongshu session halted: ...")`, so core records `xiaohongshu search failed: ...` as a visible error and stops the platform; no further page or query is attempted.
- Pinned MediaCrawler commit lives in `settings.py::PINNED_COMMIT` and in README step 1. Bump both together after re-running the fixture-based mapping tests against a real output sample.
- Settings: `XhsSettings` reads `(REPO_ROOT/.env, .env)` with `extra="ignore"` and `env_ignore_empty=True`; a relative `CLIPSIEVE_XHS_MEDIACRAWLER_DIR` resolves against `REPO_ROOT`. The CDP port is owned by core `Settings.clipsieve_xhs_chrome_cdp_port`; do not re-declare it here.
- `XhsMediaCrawlerAdapter.from_settings(settings)` is what the registry calls; the constructor's `runner`, `http`, `raw_dir`, `cache_dir` and `now` arguments exist for tests. `healthcheck` delegates to the runner.
- `search` asks the runner for one page at a time (`start_page` 1, 2, ...) per query, until `limit` posts are yielded or a page adds no new note; notes are deduped by id across pages and queries, and queries for other platforms are skipped. Each page is one full MediaCrawler run (`mediacrawler`) or one search request plus one detail request per note (`api`), so `limit` is the real cost control, bounded by `CLIPSIEVE_XHS_MAX_PAGES` per query, both runners (default 10; a `xhs.page_cap` warning marks a query that stopped short of `limit`). `CLIPSIEVE_XHS_NOTE_KINDS=video` drops image notes before the raw payload or media cache is written; the `api` runner asks the server for video notes only (`note_type=1`), while the pinned MediaCrawler always searches all note types, so with `mediacrawler` the filter is client-side and a video-only run needs more pages.
- Raw payloads go to `incoming_dir(data_dir, "xiaohongshu")/<safe_id>.json` as `{"note", "comments", "query"}`; `Post.raw_ref` is that absolute path and the core Runner relocates the file (overview B.1/B.10). Stored payloads drop comment `creator_hash`, `nickname`, `pictures` and the note's `xsec_token`; `Post.url` keeps `note_url`'s query string (only the fragment is dropped) because Xiaohongshu requires `xsec_token` to open a note page; it is a share token, not a creator identifier; the `Post` is still mapped from the unstripped records in memory.
- Media URLs are cached by the adapter in `<data_dir>/adapter-cache/xiaohongshu/<safe_id>.media.json` as `{"urls": [...]}` (written by `search`, read by `media_urls_for`: memory first, then disk). `fetch_media` never reads the raw payload or `raw_ref` because the Runner relocates it first, so a second process can fetch media after a restart. A missing entry raises `MediaDownloadError` (imported from `clipsieve.adapters.base`, never redefined) before `dest` is created.
- `fetch_media` downloads with the adapter's `httpx.Client` (30 s timeout, `Referer: https://www.xiaohongshu.com/`, streamed to `<name>.part` then renamed) into `dest` as `video.mp4` (first cached URL; the rest are lower-quality streams) or `img_00.jpg`, `img_01.jpg`, ... (always `.jpg`, overview B.2); `Media.local_path` is dest-relative. Existing non-empty files are not re-downloaded. A non-2xx response or network error raises `MediaDownloadError`.
- `map_note` maps only what core `Comment` defines (`text`, `likes`; top 50 top-level comments by likes). Media entries carry type and index only; URLs come from `image_urls`/`video_urls` for the adapter's media cache.
- Mapping is table-driven in `mapping.py::FIELD_MAP`, the single override point: `adapter.py` reads note ids and types only through `mapping.note_id`/`note_type`, so `Post.id`, the raw file name and the media-cache key stay consistent. Unverified MediaCrawler details (date format in filenames, `tag_list` delimiter, `time` unit) are fixed there, not in logic.
- Tests never start MediaCrawler, Chrome or the network. The api runner is tested with injected fakes (`cookies_provider`, `client_factory`, a fake signer) and `respx`. `FakeRunner` in `tests/conftest.py` replays `tests/fixtures/mediacrawler-output/`; media downloads are mocked with `respx`. `tests/test_adapter.py` also runs the shared `backend/tests/adapters/contract.py::run_adapter_contract`, loaded by file path because `tests` is this package's test module name too.

## Layout

- `clipsieve_xhs/settings.py` env settings (`CLIPSIEVE_XHS_*`).
- `clipsieve_xhs/runner.py` MediaCrawler runner: argv, subprocess, healthcheck, output discovery.
- `clipsieve_xhs/errors.py` api runner exceptions (`XhsApiError`, `XhsLoginRequired`, `XhsRateLimited`).
- `clipsieve_xhs/cdp_cookies.py` reads the xiaohongshu.com cookies from the browser over CDP.
- `clipsieve_xhs/api_client.py` signed, paced httpx client for search, note detail and comments.
- `clipsieve_xhs/api_runner.py` `XhsApiRunner`: search page to MediaCrawler-shaped records; halt state.
- `scripts/probe_api_runner.py` manual live probe (never run by tests); `--search-only` is one request.
- `clipsieve_xhs/mapping.py` MediaCrawler record -> `Post`.
- `clipsieve_xhs/adapter.py` the `Adapter` implementation, raw payload writer and media-URL cache.
- `tests/fixtures/mediacrawler-output/` three realistic notes and their comments.
- `tests/fixtures/xhs-api/` synthetic search, feed and comments responses.
- Lint: `pyproject.toml` extends `../../backend/pyproject.toml` (ruff `E F I UP B T20`, line length 100); `clipsieve` and `clipsieve_xhs` are one isort group. Run `uv run ruff check . && uv run ruff format --check .` here.
